# 路线图

AI量化交易分析平台的项目计划。立项日期 2026-10-21；每个阶段写明要做什么、怎样算完成。

## 目标

一个人用的美股投资平台，三件事在同一个网站、同一个登录下：

1. **记账**：真实的交易、国债定存和现金，成本和盈亏自动算好（持仓账本）。
2. **分析**：想买一只股票时，给出趋势和风险、基本面、AI 评级、和现有持仓的关系，以及按自己的规则最多能买多少（个股分析）。
3. **管理持仓**：每天按自己设定的规则检查持仓，给出建议订单；自己逐条确认、自己去券商下单（我的持仓）。

## 不变的原则

- **系统不替你下单。** 建议订单只来自你设定的规则；趋势、基本面、AI 评级只作提醒。实盘需要同时满足三件事：配置里打开开关、接入券商连接器、模拟盘已满 8 周。
- **只有一个使用者。** 量化分析只对指定的账本账号开放；账本本身可以给别人注册使用，互相隔离。
- **AI 费用有上限。** 每月 100 元以内，排队时和运行前各检查一次预算。
- **密钥不出现在代码、日志和聊天里。** 密钥由本人输入（输入时不显示），只检查“是否已配置”。
- **研究结论按预登记。** 先写下检验标准再看考试期结果，不通过就如实记录（见机器学习预登记实验 v2：未通过）。

## 阶段 1：AI 研报在服务器上运行 ✅

给 TradingAgents 加一个 `quantlab` 数据来源（[cn_vendor.py](../quantlab/src/quantlab/ai/cn_vendor.py)、[news.py](../quantlab/src/quantlab/ai/news.py)），注册进它的数据路由表，并把几处直接调用 Yahoo 的地方（K 线加载、核实快照、结算收盘价、公司简介）指向量化分析的数据。不改它的代码，也不 fork：

| TradingAgents 的工具 | 改用 |
| --- | --- |
| `get_stock_data` 日线 | 量化分析已有的国内行情（腾讯 + 新浪） |
| `get_indicators` 技术指标、核实快照 | TradingAgents 自己的计算，换成同一份日线 |
| `get_balance_sheet` / `get_income_statement` / `get_cashflow` | SEC EDGAR（TradingAgents 已支持，服务器可以访问） |
| `get_fundamentals` 概况、公司简介 | SEC 财报和登记信息 + 行情算出的市值、市盈率、市净率；基金用腾讯的名称 |
| `get_insider_transactions` | Finnhub（来自 SEC Form 4），只用分析日期之前申报的记录 |
| `get_news` / `get_global_news` | Finnhub 新闻 + 公司在 SEC 的公告（8-K 重大事件、季报年报）；Alpha Vantage 的新闻接口免费 key 不能用，已放弃 |

**完成标准和结果（2026-10-21，新服务器，按 10/20 收盘）**

- [x] 在服务器上分析 QQQM 和 VOO 各一次，全程不访问 Yahoo：运行时在网络层记录解析的域名并拦截 Yahoo，两次都是 0 次尝试。
- [x] 单次费用不超过 ¥1.5：QQQM ¥0.95（18 次调用，5 分 18 秒），VOO ¥1.10（19 次调用，5 分 26 秒）。
- [x] 引用的数据正确：QQQM 报告里的 9 个价格和指标（收盘价、成交量、50/200 日线、RSI、ATR、VWMA、10 日 EMA、前低）用服务器数据重算，全部一致；VOO 收盘价一致。
- [x] 适配器有单元测试（15 个，测试中 yfinance 一调用就报错）；数据缺失时报告明确写出（QQQM 那次还没有新闻源，报告开头列出了数据可用性声明）。

服务器上需要的密钥：`DEEPSEEK_API_KEY`、`SEC_EDGAR_USER_AGENT`、`FRED_API_KEY`、`FINNHUB_API_KEY`。

## 阶段 2：整个平台搬到新服务器（等备案）

持仓账本和量化分析一起搬到新服务器，用 wwz.hk.cn 访问；旧服务器（stock.wwz.cool）先保留，切换完成后再决定是否停用。

迁移时的步骤（备案通过后；搬数据前先确认）：

0. 新服务器：nginx、HTTPS 证书、账本和量化分析的系统服务、平台登录（和旧服务器相同的 `/lab/` 结构）。账本数据库从旧服务器复制。

1. 备份本地全部数据。
2. 把 `paper.db`、`ai.db`、`trading.db`、持仓规则和模型复制到服务器，并检查数据库版本。
3. 打开服务器的每日任务。
4. 关掉本地的开机自启。

**完成标准**：服务器连续一周每天按时完成 AI 分析、模拟盘记录和持仓检查；本地不再运行。

## 阶段 3：运维

- 量化分析数据每日备份（保留 30 份），和账本备份放在一起；写清楚怎么恢复，并实际恢复一次。
- 一条命令部署：从仓库构建、上传、安装、重启、健康检查，失败时自动回到上一版。
- 健康检查和提醒：服务挂掉、每日任务失败、AI 预算用到 80% 时通知本人。
- 日志轮转；服务器内存和磁盘占用的上限和告警。

**完成标准**：演练一次“服务器重装后从备份恢复”，全部功能可用。
